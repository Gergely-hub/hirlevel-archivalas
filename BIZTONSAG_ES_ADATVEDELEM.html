Biztonsági és Adatvédelmi Nyilatkozat

Hírlevél követő – Asztali Alkalmazás

Utolsó módosítás: 2026. október

1. Bevezetés

Ez a dokumentum ismerteti az alkalmazás biztonsági jellemzőit, a feldolgozandó adatok védelmét, valamint az Ön által vállalt biztonsági felelősséget a Hírlevél követő asztali alkalmazás használata során.

📌 Fő biztonsági megállapítás: Az alkalmazás 100%-ban helyi feldolgozást nyújt. Az adatok nem kerülnek fejlesztői szerverekre, nincs központi szinkronizálás vagy telemetria. Az adatvédelem az Ön operációs rendszer biztonságára és számítógép-fizikai biztonságára támaszkodik.

2. Architektúra és Adatok Helye

2.1 Helyi Adatfeldolgozás

  • Feldolgozás: Az alkalmazás minden műveletet az Ön Windows-számítógépén végez
  • Tárolás: Az összes adat az alábbi helyre kerül: %LOCALAPPDATA%\HirlevelKoveto\
  • Konkrét útvonal: C:\Users\[YourUsername]\AppData\Local\HirlevelKoveto\

2.2 Nincs szerverkommunikáció

  • ✓ Az alkalmazás nem kommunikál fejlesztői szerverekkel
  • ✓ Nincs telemetria vagy nyomon követés
  • ✓ Nincs automatikus frissítés-ellenőrzés
  • ✓ Nincs analytics

3. Tárolt Adatok és Biztonsági Jellemzőik

3.1 config.json – IMAP Hitelesítés

⚠️ KRITIKUS: Nincs titkosítva!

Tartalom: IMAP-szerver, e-mail cím, jelszó/alkalmazásjelszó; Outlooknál OAuth access/refresh token

Biztonsági státusz:

  • ✗ TITKOSÍTÁS: Nincs titkosítva
  • ✗ FIZIKAI BIZTONSÁG: Ha valaki hozzáféréshez jut az Ön számítógépéhez, szoftverrel kiolvasható

Biztonsági Javaslatok:

  1. Gmail-nál (és hasonló szolgáltatóknál): Használjon alkalmazásjelszót, nem a teljes fiókjelszót
    • Google Account → Security → App passwords
    • Ez a jelszó csak az Alkalmazáshoz használható, külön visszavonható
    • Fontos: az alkalmazásjelszó is titkosítás nélkül kerül a config.json-ba — ez nem helyettesíti a BitLockert, de jobb, mint a fő jelszó megadása
  2. BitLocker: Engedélyezze a Windows lemez-titkosítást
    • Windows Pro/Enterprise: Beépített BitLocker
    • Windows Home: Device Encryption (ha elérhető)
  3. Windows-jelszó: Erős, legalább 12 karakter, egyedi

3.2 hirlevelek.db – SQLite Adatbázis

Tartalom: E-mail üzenetek, feladó, tárgy, dátum, olvasott státusz

Biztonsági státusz:

  • ✗ TITKOSÍTÁS: SQLite adatbázis nem titkosított
  • ✗ KINYERÉS: Ha valaki hozzáféréshez jut, az adatbázist máshol megnyithatja

Megoldás: BitLocker lemez-titkosítás védelemmel ellátott.

4. Biztonsági Ajánlások Lépésről Lépésre

✓ Első Telepítéskor

  1. GitHub-ról töltse le az alkalmazást (nem más forrásokból)
  2. Antivírus szoftverrel ellenőrizze az EXE-fájlt
  3. Csomagolja ki a GitHub Release zip csomagját, majd indítsa a HirlevelKoveto.exe fájlt (nincs aláírt Setup)

✓ Az Alkalmazás Konfigurálása

  1. Gmail-nál: Alkalmazásjelszót generáljon
  2. Outlooknál: Microsoft bejelentkezés a programban; a token a config.json-ban marad
  3. config.json: Ne módosítsa manuálisan, ne ossza meg

✓ Folyamatos biztonság (rendszeres)

Intézkedés Gyakorisag Fontosság
Windows-frissítések Hetente 1x Kritikus
Antivírus vizsgálat Hetente 1x Magas
Biztonsági mentés (export) Hetente-havonta Magas
Alkalmazás frissítések Havonta 1x (ellenőrzés) Közepes

5. Biztonsági Ellenőrzési Lista

☐ Erős Windows-jelszó – Egyedi, legalább 12 karakter
☐ BitLocker engedélyezve – Lemez titkosítás (Windows Pro/Enterprise)
☐ Antivírus aktív – Windows Defender vagy másik
☐ Windows-frissítések – Automatikus vagy hetente
☐ Alkalmazásjelszó – Gmail-nál App Password használata
☐ Biztonsági mentés – Hetente/havonta export
☐ Zárolt képernyő – Munkahely elhagyásakor Win+L
☐ Fizikai biztonság – Ne hagyja felügyelet nélkül az nyitott laptopot

6. Biztonsági incidensek

Ha gyanítja, hogy az IMAP jelszó kompromittálódott:

  1. Azonnal módosítsa az IMAP-jelszavát
  2. Google Fiók (Gmail-nál): https://myaccount.google.com/security → Jelszó módosítása
  3. Az Alkalmazásban: Levelezés → Levelező fiókok… → fiók törlése vagy új jelszó / új Microsoft bejelentkezés
  4. Outlooknál: Microsoft fiók → Biztonság → „Bejelentkezési mód” / app-hozzáférés visszavonása
